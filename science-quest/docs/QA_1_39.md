# v1.39 save-conflict verification

Date: 2026-09-29. Build: 1.39.0. Environment: the user’s desktop Google Chrome, controlled through native accessibility UI. A separate local origin, `http://127.0.0.1:5199/`, isolated test saves from the live GitHub Pages game. No live explorer was deleted or edited.

## Automated coverage

207 test groups passed. Storage tests use separate module instances and connections against fake IndexedDB: simultaneous competing writers; event-only revision changes; stale imports/deletions/archive attempts; older snapshot writers without revision metadata; rollback after duplicate event failure; atomic profile/evidence deletion. A DOM test covers persistent warning, backup content, close warning and blocked update activation. These test doubles alone do not prove browser operation.

## Observed Chrome workflow

1. Opened test tab A; the game created the initial Explorer and displayed version 1.39 with a saved checkpoint.
2. Opened tab B against the same origin. Settings reported IndexedDB. Created a test explorer named “Two-tab checkpoint”; the footer confirmed a saved checkpoint.
3. Returned to tab A without reloading. Opened Rover Rescue. Its stale checkpoint was rejected. A persistent warning offered backup export, and the footer reported save failure.
4. Used the warning’s export button. Chrome reported `science-quest-backup.json`, 2,103 bytes, Done. The file contains tab A’s one profile, Rover Rescue notice-stage run, and first-visit/mission-open/export events.
5. Reloaded tab B. Its active “Two-tab checkpoint” explorer was still present, confirming the stale write had not replaced the newer snapshot.
6. Imported tab A’s backup using Settings and the native file picker. The game confirmed existing discoveries were preserved and showed Explorer, Two-tab checkpoint, and Explorer (imported).
7. Exported the merged save as `science-quest-backup (1).json`. Both files passed the actual application save and shared-save validators. The imported explorer has a new ID, its Rover Rescue run exactly equals the original backup’s run, and its remapped evidence includes the previously rejected mission-open and export events.

Backup SHA-256 values:

- Original: `a5d359c69747868e773291716c8c1319157d0a84a37980ae00c0354fdd6959dc`
- Merged: `2939296f18748e0432474c9e6d9a452e403d90f64e0972e70c1f0f4f60e0bc21`

The original downloads remain available locally. A native screenshot and accessibility observations showed the three-profile recovery result. The screenshot includes browser chrome, so it is not published with the public source.

## Limits

This establishes one desktop IndexedDB conflict/export/import workflow. It does not establish simultaneous localStorage-fallback safety, automatic merging, old-client cooperation, mobile behavior, timing targets, offline updates, live cloud operation or scientific/educator acceptance. Browser-provider automation still failed initialization; only native Chrome controls were usable during this check.
